# AGENTS.md

pnpm monorepo. Root package = SST-deployed trading workers (AWS Lambdas). `apps/web` = TanStack Start positions dashboard, deployed SEPARATELY (not via SST) as `node .output/server/index.mjs`. The two are independent — changes to one rarely touch the other.

## Hard rules
- NEVER read, print, or open any `.env.local` file (contains live secrets/keys). Use `.env.example` as the source of truth for env var names.
- NEVER alter the database. No writes to Supabase, Postgres, or the `exchange`/`ticker` tables. Never run migrations, seed scripts, or `genDBTypes`-adjacent mutations against the live project. The codebase is read-only with respect to the database.

## Commands
- `pnpm lint` — biome lint (root only; no format/typecheck script at root)
- `pnpm dev:web` — web dev server on :3000 (`--filter web dev`)
- `pnpm build:web` — `vite build` + `tsc --noEmit` (the ONLY typecheck; run after editing web code)
- `pnpm start:web` — run the built web server from `.output/`
- `pnpm genDBTypes` — regenerates root `database.types.ts` from Supabase project `lapkwtulywsjfjogngcx`. The web app keeps its OWN copy at `apps/web/src/lib/database.types.ts` (regenerate separately via `apps/web`'s genDBTypes). They are NOT shared — README is stale on this.
- No tests exist (`pnpm test` just exits 1).

## SST deployment
- Requires `pnpm sso` (aws sso login) first; `sst.config.ts` pins the `admin` AWS profile.
- `pnpm sst dev` for local lambda dev; `pnpm sst deploy --stage dev|production`. `production` is `protect` + `retain` (won't be destroyed on teardown).
- Secrets are `pnpm sst secret set <NAME>` and linked to functions via `link:` in `sst.config.ts` — completely separate from the web app's env.

## Web app gotchas
- Env vars validated at startup by `@t3-oss/env-core` (`apps/web/src/lib/env.ts`); a missing server var crashes the app loudly. Copy `apps/web/.env.example` → `.env.local` (do not read the contents of an existing `.env.local`). `server` vars are never bundled to the browser; `VITE_` prefix required for client vars.
- better-auth (`apps/web/src/lib/auth.ts`) is SERVER-ONLY — import it only from server functions or `/api/auth` routes. `tanstackStartCookies()` must remain the LAST plugin. GitHub signup is disabled (existing users only).
- In `routes/`, files prefixed `-` (e.g. `-positions-server.ts`) are NOT routes — they're co-located server modules; real routes are colocated under `_authenticated/`.
- Server functions use `createServerFn().handler()` and can be called straight from route loaders; they run server-side only.
- `apps/web/src/routeTree.gen.ts` is auto-generated by TanStack Router (regenerated on dev/build, excluded from biome) — never hand-edit.

## Trading code
- All allocation math uses `bignumber.js` (`BN`) — never raw floats for sizes/allocation.
- Hyperliquid integration uses `@nktkas/hyperliquid` (`HttpTransport` + `InfoClient`); docs MCP is available (nktkas/hyperliquid and hyperliquid).
- Worker entrypoints: `src/trade-{extended,hyperliquid,risex}.handler`, orchestrated by the cron `src/timestamp-checker` → SNS error topic → `src/notifier`.

## Dependencies
- `pnpm-workspace.yaml` enforces a 7-day `minimumReleaseAge` supply-chain gate; `apps/web` pins fast-moving framework packages (react-start/router, vite) to exact versions from a batch that predates the cutoff. Bumping them requires picking versions ≥7 days old or adding a `minimumReleaseAgeExclude` entry (see README).
- Git-aware biome ignores `.sst/` and `.output/`.
